# ၁ — VXLAN-EVPN ကို အဘယ်ကြောင့် သုံးသနည်း {: #1-why-vxlan-evpn }

*မည်သို့လုပ်ဆောင်သည်* မတိုင်မီ *အဘယ်ကြောင့်သုံးသည်* ကို ဦးစွာနားလည်ပါ။ VXLAN-EVPN ပေါ်ပေါက်လာရခြင်းမှာ ရိုးရာ Layer-2 ကွန်ရက်များသည် data center အတွင်း ကြီးမားသော အကန့်အသတ်များနှင့် ရင်ဆိုင်ခဲ့ရသောကြောင့် ဖြစ်ပါသည်။

## ရိုးရာ L2 (VLAN + Spanning Tree) ကွန်ရက်များ၏ ပြဿနာများ {: #the-problems-with-a-classic-l2-network }

| ပြဿနာ | ထိခိုက်နစ်နာရသည့် အကြောင်းရင်း |
|---------|--------------|
| **Spanning Tree သည် Link များကို ပိတ်ပင်သည်** | STP သည် loop မဖြစ်စေရန် အရန် (redundant) link များကို *ပိတ်ထား (disable)* ရသည်။ လမ်းကြောင်းများစွာရှိသော fabric တစ်ခုတွင် သင်သည် အသုံးမပြုနိုင်သော link များအတွက် ငွေကုန်ကြေးကျ ခံနေရပြီး — load balancing မရရှိနိုင်ပါ။ |
| **VLAN ကန့်သတ်ချက် = ၄၀၉၄** | 802.1Q tag သည် 12 bits သာရှိသည်။ Multi-tenant cloud စနစ်တစ်ခုသည် အပိုင်း ၄၀၉၄ ခုထက် များစွာ ပိုမိုလိုအပ်သည်။ |
| **MAC Table ကြီးမားလာမှု** | Switch တိုင်းသည် L2 domain တစ်ခုလုံးရှိ MAC address *အားလုံး* ကို မှတ်သားထားရသည်။ ကြီးမားသော flat network များသည် hardware table များကို ပြည့်လျှံစေသည်။ |
| **ကျရှုံးမှု နယ်ပယ် ကျယ်ပြန့်ခြင်း (Large failure domains)** | Broadcast storm သို့မဟုတ် loop တစ်ခု ဖြစ်ပွားပါက L2 domain တစ်ခုလုံး ပြိုလဲသွားစေသည်။ |
| **Workload များ လွတ်လပ်စွာ မရွှေ့ပြောင်းနိုင်ခြင်း** | Subnet တစ်ခုနှင့် ချိတ်ဆက်ထားသော VM တစ်ခုသည် IP ပြန်မပြောင်းဘဲ သို့မဟုတ် VLAN များကို အတင်းဆွဲမဆန့်ဘဲ အခြား rack တစ်ခုသို့ ရွှေ့ပြောင်း၍ မရနိုင်ပါ (VLAN ဆွဲဆန့်ခြင်းက အထက်ပါပြဿနာများကို ပိုဆိုးစေသည်)။ |

## Data Center တစ်ခုအတွက် အမှန်တကယ် လိုအပ်ချက်များ {: #what-the-data-center-actually-needs }

- **Link တိုင်းကို အပြည့်အဝ အသုံးချနိုင်ခြင်း** — equal-cost multipath (ECMP)၊ ပိတ်ထားသော port လုံးဝမရှိခြင်း။
- **ကြီးမားသော စကေး (Massive scale)** — ထောင်ဂဏန်း မဟုတ်ဘဲ သန်းနှင့်ချီသော segment များ။
- **မည်သည့်နေရာတွင်မဆို မည်သည့် Workload မဆို ထားရှိနိုင်ခြင်း** — VM တစ်ခုသည် မည်သည့် leaf ပေါ်တွင်မဆို ရှိနေနိုင်ပြီး ၎င်း၏ မူလ IP ကို မပြောင်းလဲဘဲ ထိန်းသိမ်းထားနိုင်ခြင်း။
- **Multi-tenancy** — သီးခြားခွဲထုတ်ထားသော tenant များစွာသည် ရုပ်ပိုင်းဆိုင်ရာ physical fabric တစ်ခုတည်းကို မျှဝေသုံးစွဲနိုင်ခြင်း။
- **ကျရှုံးမှု နယ်ပယ် ကျဉ်းမြောင်းခြင်း** — Leaf တစ်ခုပေါ်တွင် ဖြစ်ပွားသော ပြဿနာသည် ထိုနေရာတွင်သာ ကန့်သတ်တည်ရှိနေခြင်း။

## VXLAN-EVPN က ၎င်းတို့ကို မည်သို့ ဖြည့်ဆည်းပေးသနည်း {: #how-vxlan-evpn-delivers-it }

**VXLAN** (data plane) သည် Ethernet frame များကို UDP/IP ထဲသို့ ထည့်သွင်း (encapsulate) ပေးသဖြင့် Layer-2 သည် **routed** Layer-3 network ပေါ်တွင် စီးနင်းလိုက်ပါသွားနိုင်သည်:

- L3 underlay သည် သမားရိုးကျ routing (OSPF/IS-IS/BGP) ကို သုံးသည် → **ECMP ရရှိသည်၊ link အားလုံး တက်ကြွသည်၊ leaf များနှင့် spine များကြား spanning tree မရှိပါ**။
- Segment ID (VNI) သည် **24 bits ရှိသဖြင့် ~၁၆ သန်းသော** segment များကို ရရှိစေသည် (၄၀၉၄ မဟုတ်ပါ)။
- အောက်ခံတွင် routed ဖြစ်သောကြောင့် host တစ်ခု၏ L2 segment ကို **မည်သည့် leaf ဆီသို့မဆို ဆွဲဆန့်နိုင်သည်** — workload mobility ရရှိစေသည်။

**EVPN** (control plane) သည် ရှေးဟောင်း "flood and learn" လုပ်ငန်းစဉ်ကို BGP ဖြင့် အစားထိုးပေးသည်:

- VTEP များသည် MAC များကို ရှာဖွေရန် broadcast flooding လုပ်မည့်အစား BGP မှတစ်ဆင့် မိမိတို့၏ local MACs/IPs များကို အချင်းချင်း **ကြေညာပေးပို့ကြသည် (advertise)**။
- **ARP suppression**၊ မြန်ဆန်သော convergence၊ multihoming၊ နှင့် integrated routing/bridging (IRB) တို့ကို အထောက်အပံ့ပေးသည်။

## စိတ်ထဲစွဲမြဲရမည့် အကျဉ်းချုပ် စကားစု {: #the-one-liner-to-remember }

> **VLAN သည် ဝါယာကြိုးတစ်ချောင်းတည်းကို အများအပြားဖြစ်အောင် ခွဲထုတ်ပြသည်။ VXLAN သည် ဝါယာကြိုးများစွာ (routed fabric တစ်ခုလုံး) ကို ဝါယာကြိုးတစ်ခုတည်းအဖြစ် ပေါ်လွင်စေသည် — EVPN ကမူ ၎င်းပေါ်တွင် မည်သူရှိနေကြောင်းကို စောင့်ကြည့်မှတ်သားပေးသည်။**

## မိမိကိုယ်ကို ပြန်လည်စစ်ဆေးပါ {: #check-yourself }

1. Spanning-tree ကွန်ရက်တစ်ခုသည် ၎င်း၏ link အားလုံးကို အဘယ်ကြောင့် အသုံးမပြုနိုင်သနည်း၊ routed underlay တစ်ခုက ၎င်းကို မည်သို့ ဖြေရှင်းပေးသနည်း။
2. VLAN များ၏ တင်းကျပ်သော ကန့်သတ်အရေအတွက်မှာ အဘယ်နည်း၊ VXLAN ၏ ကန့်သတ်ချက်မှာ အဘယ်နည်း။
3. တစ်ကြောင်းစီဖြင့် ဖြေဆိုပါ: **VXLAN** က မည်သည့်အရာကို လုပ်ဆောင်သနည်း နှင့် **EVPN** က မည်သည့်အရာကို လုပ်ဆောင်သနည်း။
