# ၄ — EVPN Control Plane {: #4-evpn-control-plane }

သင်ခန်းစာ ၃ တွင် frame တစ်ခုသည် fabric ကို မည်သို့ဖြတ်သန်းသွားသည်ကို လေ့လာခဲ့ပြီးဖြစ်သည်။ ဤသင်ခန်းစာက မေးခွန်းထုတ်ပါသည်: **VTEP တစ်ခုသည် ထို frame ကို မည်သည့်နေရာသို့ ပို့ရမည်ကို မည်သို့ သိရှိသနည်း။** ထိုအရာသည် control plane ဖြစ်သည် — ၎င်းသည်ပင် VXLAN-EVPN အား သမားရိုးကျ VXLAN ထက် များစွာ ပိုမိုကောင်းမွန်စေသောအချက် ဖြစ်ပါသည်။

## EVPN က ဖြေရှင်းပေးသော ပြဿနာ {: #the-problem-evpn-solves }

EVPN မပါဝင်သော ရိုးရိုး Plain VXLAN သည် ရှေးဟောင်း L2 ကဲ့သို့ပင် **flood-and-learn** ကိုသာ လုပ်ဆောင်နေဆဲဖြစ်သည်: မသိရှိသော MAC တစ်ခုကို ရှာဖွေရန် နေရာအနှံ့သို့ flood လုပ်ပြီး ပြန်လာသော reply မှတစ်ဆင့် မှတ်သားရသည်။ ထိုသို့ပြုလုပ်ခြင်းသည် scale ချဲ့ရန် မဖြစ်နိုင်သလို bandwidth ကိုလည်း အလဟဿ ဖြုန်းတီးစေပါသည်။

**EVPN သည် flooding ကို သတင်းအချက်အလက် ကြေညာခြင်း (advertising) ဖြင့် အစားထိုးလိုက်ပါသည်။** VTEP တစ်ခုချင်းစီသည် မည်သည့် MAC များနှင့် IP များသည် မိမိနောက်ကွယ်တွင် ရှိနေကြောင်းကို BGP ကို အသုံးပြု၍ အခြားသူများထံသို့ *ပြောပြကြသည် (tells)*။ Flooding ဖြင့် လိုက်ရှာစရာ မလိုတော့ပါ။

## EVPN သည် BGP Address Family တစ်ခုဖြစ်သည် {: #evpn-is-a-bgp-address-family }

EVPN သည် protocol အသစ်စက်စက်တစ်ခု မဟုတ်ပါ — ၎င်းသည် **MP-BGP တွင် သယ်ဆောင်လာသော address family အသစ်** တစ်ခု ဖြစ်ပါသည်:

- Junos တွင် `family evpn signaling` / Cisco တွင် `address-family l2vpn evpn`။
- နည်းပညာအရ **AFI 25 (L2VPN), SAFI 70 (EVPN)** ဖြစ်သည်။
- သင် run ထားပြီးဖြစ်သော BGP session များပေါ်တွင်ပင် စီးနင်းလိုက်ပါသည် — Lab ထဲတွင် leaf loopback များကြားရှိ iBGP session ဖြစ်သည်။

ထို့ကြောင့် leaf များသည် BGP ပေါ်တွင် peer ပြုလုပ်ကြပြီး *"MAC aa:bb:cc, IP 10.100.10.11 သည် VTEP 10.0.0.22 ၏ နောက်ကွယ်၊ VNI 10100 တွင် ရှိသည်"* စသည့် **EVPN route များကို** (နောက်သင်ခန်းစာတွင် ဖော်ပြမည်) အပြန်အလှန် လဲလှယ်ကြပါသည်။

## မဖြစ်မနေ သိရှိထားရမည့် အမှတ်အသားနှစ်ခု: RD နှင့် RT {: #two-identifiers-you-must-know-rd-and-rt }

လူအများ စိတ်ရှုပ်ထွေးတတ်သော အပိုင်းဖြစ်ပြီး အင်တာဗျူးများတွင် သေချာပေါက် မေးလေ့ရှိသည့် ခေါင်းစဉ်ဖြစ်ပါသည်:

### Route Distinguisher (RD) {: #route-distinguisher-rd }
- VTEP တစ်ခုချင်းစီ၏ route များကို **တစ်မူထူးခြားစေရန် (unique)** ပြုလုပ်ပေးသည်။ Leaf နှစ်ခုလုံးက `10.100.10.0/24` ကို ကြေညာကောင်း ကြေညာနိုင်သည်၊ RD မပါပါက BGP ထဲတွင် ထပ်တူကျနေမည်ဖြစ်သည်။
- Route ၏ ရှေ့တွင် ထည့်သွင်းထားသည်: ဥပမာ `10.0.0.21:1`။ ရည်ရွယ်ချက်မှာ သီးသန့် **uniqueness** အတွက်သာ ဖြစ်သည်။
- Lab ထဲတွင် leaf တစ်ခုစီ၌ မတူညီသော RD များ သတ်မှတ်ထားသည် (`10.0.0.21:1` နှင့် `10.0.0.22:1`)။

### Route Target (RT) {: #route-target-rt }
- **Import/Export** မူဝါဒကို ထိန်းချုပ်သော extended community ဖြစ်သည် — *မည်သည့်* VTEPs/VRFs များက route တစ်ခုကို လက်ခံရမည်ကို သတ်မှတ်သည်။
- VTEP တစ်ခုသည် RT ဖြင့် tag တွဲထားသော route များကို **ထုတ်ပေးသည် (exports)**၊ မိမိသတ်မှတ်ထားသော RT နှင့် ကိုက်ညီသည့် route များကို **လက်ခံယူသည် (imports)**။ RT တူညီခြင်း = virtual network တစ်ခုတည်း ဖြစ်ခြင်း။
- Lab ထဲတွင် leaf နှစ်ခုလုံးသည် *တူညီသော* RT (`target:65000:1`) ကို မျှဝေသုံးစွဲထားကြသည် — ထို့ကြောင့် VNI တစ်ခုတည်းတွင် အတူတကွ ရှိနေရန် သဘောတူညီကြခြင်း ဖြစ်သည်။

> **RD = တစ်မူထူးခြားမှု (uniqueness)။ RT = အဖွဲ့ဝင်ဖြစ်မှု (membership)။** Box တစ်ခုစီအတွက် မတူညီသော RD၊ VNI တစ်ခုစီအတွက် တူညီသော RT။

## EVPN က ပေးစွမ်းနိုင်သော စွမ်းဆောင်ရည်များ ("flooding မရှိခြင်း" အပြင်) {: #what-evpn-gives-you }

| စွမ်းဆောင်ရည် | လုပ်ဆောင်ပေးသည့် အရာ |
|---------|--------------|
| **MAC/IP ကြေညာနိုင်မှု** | အဝေးရှိ remote host များကို flooding မလိုဘဲ BGP (Type-2) မှတစ်ဆင့် သိရှိနိုင်ခြင်း |
| **ARP/ND ဖိနှိပ်ထိန်းချုပ်မှု (Suppression)** | Local leaf သည် ARP ကို မိမိ၏ EVPN ဇယားမှ တိုက်ရိုက်ဖြေကြားပေးသည် — ARP သည် fabric ကို ဖြတ်သန်းစရာ မလိုတော့ပါ |
| **လျင်မြန်သော Convergence** | Host တစ်ခု ရွှေ့ပြောင်းသွားပါက flooding မလိုဘဲ BGP update တစ်ခုဖြင့် ချက်ချင်း သိရှိနိုင်ခြင်း |
| **Multihoming (ESI)** | Host တစ်ခုသည် leaf နှစ်ခုနှင့် တပြိုင်နက် ချိတ်ဆက်နိုင်ပြီး နှစ်ခုလုံး တက်ကြွစွာ အလုပ်လုပ်နိုင်ခြင်း (all-active) |
| **Integrated Routing & Bridging (IRB)** | Leaf ပေါ်တွင် VNI များကြား route လုပ်နိုင်ခြင်း (L3VNI)၊ anycast gateway အသုံးပြုနိုင်ခြင်း |

## Overlay အတွက် iBGP vs eBGP ရွေးချယ်မှု {: #ibgp-vs-ebgp-for-the-overlay }

- **iBGP** (lab 01): VTEP အားလုံးသည် AS တစ်ခုတည်းတွင် ရှိသည်။ Full mesh — သို့မဟုတ် ကြီးမားသော စကေးတွင် spine များကို **route reflectors** အဖြစ် အသုံးပြုသဖြင့် N² session များ မလိုအပ်တော့ပါ။
- **eBGP** (lab 04): Leaf တစ်ခုစီသည် မိမိ၏ သီးခြား AS ဖြင့် ရှိပြီး overlay သည် eBGP-EVPN ကို သုံးသည်။ ကြီးမားသော fabric များတွင် အသုံးများပြီး protocol တစ်ခုတည်း (eBGP) ဖြင့် underlay ရော overlay ပါ နှစ်မျိုးလုံးကို လုပ်ဆောင်နိုင်သည်။

## မိမိကိုယ်ကို ပြန်လည်စစ်ဆေးပါ {: #check-yourself }

1. EVPN သည် မည်သည့်အရာကို မည်သည့်အရာဖြင့် အစားထိုးခဲ့သနည်း။
2. EVPN ကို မည်သည့် protocol ထဲတွင် မည်သည့်ပုံစံဖြင့် သယ်ဆောင်သနည်း။
3. RD နှင့် RT အကြား ခြားနားချက်ကို ရှင်းပြပါ — မည်သည့်အရာက box တစ်ခုစီအတွက် သီးသန့်ဖြစ်ပြီး၊ မည်သည့်အရာက VNI တစ်ခုစီအတွက် တူညီသနည်း၊ အဘယ်ကြောင့်နည်း။
4. ARP suppression ဆိုသည်မှာ အဘယ်နည်း၊ ၎င်းသည် အဘယ်ကြောင့် အလွန်အသုံးဝင်သနည်း။
