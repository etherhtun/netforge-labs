# Phase 0 — IGP Fundamentals (အခြေခံ အုတ်မြစ်များ)

> 📖 **သဘောတရားဖတ်ရှုရန် — Lab မပါဝင်ပါ။** OSPF နှင့် IS-IS တို့သည် ကွန်ရက်လောကတွင် အကျယ်ပြန့်ဆုံး သင်ကြားထားပြီးသော အကြောင်းအရာများဖြစ်ပြီး ရိုးရိုး "စက် ၃ လုံးပေါ် OSPF တင်နည်း" walkthrough တစ်ခုသည် သင့်အား များစွာ သင်ကြားပေးနိုင်မည် မဟုတ်ပါ။ ဤ phase သည် နောက်ပိုင်း phases အားလုံးအတွက် လိုအပ်မည့် အခြေခံ mental model ကို ပေးစွမ်းမည် ဖြစ်ပါသည်။

ဤသင်ရိုးညွှန်းတမ်းရှိ Overlay နည်းပညာတိုင်း (VXLAN, MPLS, EVPN, Segment Routing) သည် အောက်ခံတွင် အချက်တစ်ချက်ကို အခြေပြုထားပါသည်: **Router တိုင်းသည် အခြား router တိုင်း၏ Loopback IP သို့ မည်သို့သွားရမည်ကို ကြိုတင် သိရှိပြီးဖြစ်ရမည်။** ထိုတာဝန်သည် IGP (Interior Gateway Protocol) ၏ တာဝန် ဖြစ်ပါသည်။

ဤအဆင့် မှားယွင်းပါက အထက်ရှိ မည်သည့်နည်းပညာမျှ အလုပ်လုပ်မည် မဟုတ်ပါ။ လက်တွေ့တွင် "MPLS ပျက်နေသည်" သို့မဟုတ် "EVPN peers မတက်လာပါ" ဟူသော ပြဿနာများ၏ အဖြစ်အများဆုံး အကြောင်းရင်းမှာ ပျက်စီးနေသော IGP ကြောင့်သာ ဖြစ်လေ့ရှိပါသည်။

## ကြိုတင် လိုအပ်ချက်များ

IP addressing၊ subnetting၊ နှင့် routing table နှင့် forwarding table အကြား ကွာခြားချက်တို့ကို နားလည်ထားရန် လိုအပ်သည်။ Static routes နှင့် directly-connected routes များကို သဘောပေါက်ပါက အဆင်သင့်ဖြစ်ပါပြီ။

## ဤသင်ရိုးက မည်သည့်နေရာသို့ ဦးတည်သနည်း

| နောက်တစ်ဆင့် | အဘယ်ကြောင့် ဤအဆင့်ကို လိုအပ်သနည်း |
|---|---|
| **Phase 1 · BGP** | iBGP peers သည် IGP က ရောက်ရှိပြီးဖြစ်သော Loopbacks များပေါ်တွင် ချိတ်ဆက်ရသည် |
| **Phase 3 · MPLS** | LDP သည် *IGP က table ထဲ ထည့်ပေးထားသော* prefixes များပေါ်တွင် labels ချည်နှောင်သည် — route မရှိပါက label မရှိနိုင်ပါ |
| **Phase 4 · EVPN** | VTEPs များသည် IGP ကြေညာထားသော loopbacks များမှတစ်ဆင့် tunnels တည်ဆောက်သည် |

!!! tip "အမြဲတမ်း အမှတ်ရသင့်သော ရွှေစည်းမျဉ်းတစ်ခု"
    **Underlay ကောင်းမွန်ကြောင်း မစစ်ဆေးမီ Overlay ကို ဘယ်တော့မှ debug မလုပ်ပါနှင့်။** စက်နှစ်လုံးသည် သာမန် IP ဖြင့် loopbacks အချင်းချင်း ping မရပါက overlay layer တွင် မည်မျှပင် ပြင်ဆင်ပါစေ အလဟဿသာ ဖြစ်ပါလိမ့်မည်။ စစ်ဆေးရန် စက္ကန့် ၃၀ ခန့်သာ ကြာမြင့်သော်လည်း နာရီပေါင်းများစွာ အချိန်ကုန်ခြင်းမှ ကာကွယ်ပေးပါလိမ့်မည်။
